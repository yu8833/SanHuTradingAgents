## 1. 背景与目标

本系统的交易方法论源自《Wind 交易系统·完整教材》（下称"教材"）。为把教材第六章"交易工具与日常流程"的实战要求落地到本系统，编写本设计文档。

目标：

1. 盘点本系统已具备的能力，明确哪些"工具"已完成、哪些仍需补齐；
2. 识别教材要求与本系统的差距，按优先级排序；
3. 细化 **宏观快扫（盘前）** ——教材每日流程的第一步，也是本次设计重点；
4. 形成统一实施路线图，作为后续开发依据。

## 2. 教材第六章要求提炼

### 2.1 工具体系（6.1）

| 工具 | 用途 | 市场覆盖 |
|---|---|---|
| TradingView Pine Script | 图表上实时显示买卖信号 | A股、港股、美股 |
| Wind 交易系统（本地 Web 应用） | 批量扫描全量 A 股信号 | A股 |
| ETF Radar | 行业 ETF 轮动评分 | A股（后续扩展港股美股） |
| Stock Radar | 个股多因子评分 | A股、港股、美股 |
| 实盘跟踪 Excel | 交易记录与复盘 | 全市场 |

### 2.2 每日操作流程（6.2）

- **盘前（8:00-9:15）**
  - Step1 宏观快扫（5 分钟）：隔夜美股（SPX/QQQ）、隔夜港股（恒指/恒生科技）、重大政策/事件/经济数据 → 判断今天大盘可能的方向；
  - Step2 系统信号检查（10 分钟）：查看重点标的 BIAS、MA60 方向、联动象限、买入时机，标记重点关注标的（≤5 只）；
  - Step3 制定当日计划（5 分钟）：操作决策、买入价位/仓位反算/止损位、卖出条件，写下来盘中严格执行。
- **盘中（9:30-15:00）**：9:30-10:00 观察期（不急于操作）→ 10:00-11:30 主要操作窗口（按计划执行，止损立即执行）→ 13:00-14:30 观察与调整（微调仓位）→ 14:30-15:00 收尾（不开新仓）。
- **盘后（20:00-21:00）**：Step1 更新数据（持仓总览收盘价、交易记录）→ Step2 信号扫描（浏览当日信号，记录到"信号跟踪"）→ Step3 次日计划（接近买点标的、接近止损/止盈的持仓、明日大盘预期事件）。
- **周度复盘（每周五盘后 30 分钟）**
  1. 定量统计：本周收益率（vs 沪深300）、交易笔数、胜率、持仓全红率；
  2. 定性回顾：做对了什么/做错了什么、有没有违反系统规则、三系统信号一致性；
  3. 信号有效性检查：回填 5 天前信号的实际表现，统计哪些信号有效/失效及原因；
  4. 下周计划：大盘趋势判断、关注标的与预期操作。

## 4. 缺口分析与优先级

### 缺口 1：信号跟踪 + 有效性回填（**最高优先级**）

- **教材要求**：盘后把重要信号记入"信号跟踪"；周度回填 5 天前信号的实际表现，验证有效性。
- **现状**：系统会产出信号（扫描/三买三卖）、会记录交易，但**信号本身不落库**，无法回溯"N 天后实际表现"。
- **方案**：
  - 新建 `signal_tracking` 集合：`{signal_type, code, trigger_date, snapshot(BIAS/MA60/象限/信号价), status}`，扫描时自动落库；
  - 新增定时任务：周度/每日回填 N 个交易日后实际表现（收益率、是否触止损/止盈、胜负），汇总成"按信号类型的胜率/盈亏比"；
  - 前端加"信号跟踪"页，配合现有 `PaperTrading/Review.vue`。

### 缺口 2：当日交易计划（**高优先级**）

- **教材要求**：盘前写计划，盘中按计划严格执行。
- **现状**：无"计划-执行"闭环。
- **方案**：
  - 新建 `daily_plans` 集合：`{标的, 方向, 触发价, 仓位反算, 止损位, 卖出条件, 状态(待执行/已执行/取消), executed_trade_id}`；
  - 复用 SSE 实时行情，自选/持仓价格触达计划价位时前端高亮/推送提醒；
  - 执行后自动关联 paper_trades，形成"计划→成交→复盘"链路。

### 缺口 3：周度复盘自动化（**中优先级**）

- **教材要求**：周五盘后定量统计（vs 沪深300）、定性回顾、信号有效性检查、下周计划。
- **现状**：胜率统计为全量累计，无"本周窗口 + 对标基准 + 持仓全红率"。
- **方案**：
  - 新增周报服务：从 paper_trades 聚合本周收益率/笔数/胜率；从 paper_positions 计算**持仓全红率 = 盈利持仓数 / 总持仓数**（教材 5.3 核心指标）；
  - 对比沪深300：用 Tushare 指数日线（现有同步链路已有大盘数据）；
  - 前端"周度复盘"页 + 周五盘后自动生成（挂现有调度体系）。

### 缺口 4：统一"每日操作流程"作战室页面（**中优先级**）

- **教材要求**：盘前-盘中-盘后一套可照做的流程。
- **现状**：各能力分散在复盘/候选池/持仓/筛选多个页面（现有菜单按"功能域"硬编码组织，无时间线入口）。
- **方案**（呈现方式已确认，2026-08-31）：新增**独立一级菜单"作战"**（路由 `/war-room`，内部按时间段 Tab：盘前/盘中/盘后/周度），同时在**速览 Dashboard 顶部加一条轻量"今日流程引导条"**（显示当前时段 + 待办，点击跳转"作战"对应 Tab）；宏观快扫为"作战"的盘前模块，见第 5 章细化设计。
- **前端改动点**：`frontend/src/router/index.ts`（新增 `/war-room` 路由）、`frontend/src/components/Layout/SidebarMenu.vue`（菜单为硬编码，需手动加"作战"一级菜单项）、`frontend/src/layouts/BasicLayout.vue`（keepAliveComponents 加入作战页）、`frontend/src/views/WarRoom/index.vue`（新页）。

## 5. 宏观快扫（盘前）细化设计 v1

### 5.1 已确认决策（2026-08-31 用户拍板）

1. **分析方式**：混合——规则引擎定方向（可控、可回测、可解释）+ LLM 只做可读解读（低风险、低成本）；
2. **事件/数据源**：新增**财经日历接口**（东财 datacenter 优先，AKShare 兜底，再兜底手工维护日历表）；
3. **外围范围**：在现有 5 指数基础上**扩展至 VIX/美股期货/亚太指数/富时A50期货**。

### 5.2 整体架构（四层）

```
┌─ 数据层（4 个 provider）─────────────────────────────┐
│ A. 外围指数(扩展)  B. 财经日历(新增)  C. 快讯分级(增强)  D. 大盘状态(已有) │
└──────────────────────┬──────────────────────────────┘
                       ▼
┌─ 规则引擎 macro_scorer（硬锚点）───────────────────────┐
│ 信号表打分 → 方向(偏多/中性/偏空) + 置信度 + 依据明细          │
└──────────────────────┬──────────────────────────────┘
                       ▼
┌─ LLM 解读（软解读，快速模型 1 次调用）────────────────────┐
│ 同份数据+评分 → 盘前纪要/事件影响/风格倾向/风险提示             │
└──────────────────────┬──────────────────────────────┘
                       ▼
┌─ 存储(Mongo 快照) + API + 前端盘前 tab + 调度(交易日 8:15) ─┐
```

### 5.3 数据层

**A. 外围指数扩展**（在 `app/services/vibe_gstock.py` 现有 5 指数基础上增加）

| 新增 | 作用 | 说明 |
|---|---|---|
| VIX 恐慌指数 | 风险偏好 | `<18` 偏风险偏好，`>25` 偏恐慌 |
| 标普/纳指/道指**期货** | 8 点看盘时美股已收盘约 6 小时，期货反映盘后动态 | 东财 CME 期货 secid，**容器实测** |
| 日经225 / KOSPI | 当日亚太情绪 | 东财 push2 secid |
| 富时中国 A50 期货 | 直接指向 A 股的隔夜信号 | 最有价值的一项 |

每个指数输出沿用现有结构：`{key, name, price, change_pct, region}`。

**B. 财经日历（新增 provider）**
- 首选：东财 datacenter 经济日历接口（复用现有 `_eastmoney_datacenter` 封装，零新依赖），拉取未来 7 天：中国（CPI/PPI/PMI/社融/M2/LPR/MLF）、美国（非农/CPI/PPI/利率决议/初请失业金）；
- 兜底：AKShare 宏观接口；再兜底：手工维护的"高频事件日历"表（降准降息日/议息日/数据发布日/重要会议日）；
- 输出：`{date, region, event, importance, forecast, 发布时点}`，Redis 1 天 TTL；
- **容器内先验证东财日历可用性，失败再降级**。

**C. 快讯分级（复用 + 增强）**
- 复用 `tradingagents/dataflows/news/realtime_news.py` 的财联社 + 东财 7x24 文字流；
- 新增**重要性分级规则**（关键词表）：货币政策（降准/降息/LPR/MLF/美联储）、财政（国常会/专项债）、数据（CPI/PPI/PMI/社融/非农）、地缘（关税/制裁）、监管（证监会/IPO/解禁）→ 高/中/低；
- 过去 12-24h 窗口 + 去重 + 截断 top N。

**D. 大盘自身状态**：复用 `app/services/market_dashboard.py`（涨跌家数/成交额/涨停/北向）——"外围 + 自身"双确认。

### 5.4 分析层（核心）

**A. 规则引擎 macro_scorer**（信号表，阈值可配置）

| 信号 | 打分规则 |
|---|---|
| 标普500 | >+0.5% → +1；<-0.5% → -1 |
| 纳斯达克 | >+0.8% → +1；<-0.8% → -1 |
| 恒指 / 日经 / KOSPI | >+0.5% → +1；<-0.5% → -1 |
| VIX | <18 → +1；>25 → -1 |
| 富时A50期货 / 美股期货 | 同标普规则 |
| 高重要性政策/数据事件 | 利好 +2 / 利空 -2 |
| 昨日大盘情绪 | 涨跌家数 >3:1 → +1；<1:3 → -1 |

- 聚合：总分 ≥2 偏多、≤-2 偏空、否则中性；置信度 = |总分|/满分；
- 输出：`{direction, score, confidence, signals[]}`，每条带依据——**可解释、可回测**。

**B. LLM 解读**（复用现有 LLM provider + `/api/chat` 打包模式）
- Prompt 输入：外围表 + 日历 + 分级快讯 + **规则评分结果**；
- 输出强约束（固定结构）：今日关键词 / 事件影响（今天要盯什么）/ 风格倾向（大小盘·成长价值·题材）/ 风险提示；**不做个股推荐**，只做环境解读；
- **降级**：LLM 不可用时只出规则结果并标注"解读不可用"，方向判断不受影响。

### 5.5 存储 / API / 前端 / 调度

| 项 | 方案 |
|---|---|
| 存储 | `macro_daily_snapshots` 集合（date 唯一）：`{date, indices[], calendar[], news_top[], rule{score,direction,confidence,signals[]}, llm_interpretation, created_at}`，历史可回溯，喂周度复盘 |
| API | `GET /api/macro/daily-overview`（今日或指定日期）+ `POST /api/macro/refresh`（手动触发） |
| 前端 | "作战"页盘前 tab（见第 4 章缺口4）：外围表 + 事件日历 + 方向结论标签（红/绿 + 置信度）+ 盘前纪要 + 风险提示 |
| 调度 | 交易日 8:15 自动生成落库（复用 APScheduler + `app/utils/trading_time.py` 交易日判断） |

### 5.6 实施顺序与风险

实施顺序（每步容器验证）：

1. 外围扩展（VIX/期货/亚太/A50）→ 验证取数；
2. 财经日历 provider → 验证接口，失败降级；
3. 快讯分级 → 验证关键词命中；
4. 规则引擎 + 单测（阈值/方向映射）；
5. LLM 解读 + 降级；
6. 落库 + API + 前端 + 调度；
7. 回归测试 + docker 重启验证。

风险与兜底：

- 财经日历接口 / 期货 secid 需容器实测 → 均有降级路径，不阻塞；
- LLM 成本：每次盘前 1 次快速模型调用，可忽略；
- 判定"利好/利空"的事件极性依赖关键词规则，需在快讯分级中谨慎维护词表。

### A.2 顶部横幅与流程引导条

### A.5 数据展示逻辑

| 项 | 逻辑 |
|---|---|
| 盘前静态数据 | 进入 Tab/点刷新时 `GET /api/macro/daily-overview` 一次性拉取；日历后端 Redis 1 天 TTL |
| 盘中实时 | SSE（`quotesSSE.ts`）订阅 自选+持仓+计划标的 代码，价格触达目标/止损高亮；预警复用现有机制 |
