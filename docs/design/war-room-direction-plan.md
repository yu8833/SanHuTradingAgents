# 作战室：从"环境判断"到"个股当日计划"的链路打通方案

> 状态：方案论证 + UI 原型（方向拆解面板）已完成，待选定实现范围。
> 关联：作战室盘前 Tab、`daily_plans` 手动创建、候选池/策略族/信号跟踪等既有能力均为"孤岛"，本方案描述如何打通并落地成可执行的当日计划。

## 1. 背景与目标

作战室已能给出宏观方向、置信度、重要资讯、外围市场快照、财经日历等**环境层**信息；系统也已有候选池、各类选股策略、信号跟踪、ETF 雷达等**个股层**能力；`daily_plans` 提供了"单条当日计划"的容器，但目前只能**手动逐条创建**。

目标：把「环境判断」和「个股候选」打通，生成**具体到股票代码、方向、触发价、止损、仓位的当日计划**，并让每个结论**可拆解、可溯源、可否决**，从而"看得懂也信服"。

存在两块明显可知的问题，构成本方案要解决的核心：

1. 宏观方向在盘中反复横跳，缺乏"当日基准"的稳定性。
2. 没有一个"环境 → 行业 → 个股 → 计划"的聚合/编排层，候选不能自动落到 `daily_plans`。

## 2. 现状盘点（孤岛）

| 已有能力         | 产出                              | 到代码？    | 位置                                                         |
| ------------ | ------------------------------- | ------- | ---------------------------------------------------------- |
| 作战室宏观        | 方向/置信度/日历/快讯/外围/宽度              | 否（大盘贝塔） | `app/services/macro/*`、`app/routers/war_room.py`           |
| 候选池          | 强势行业 → 成分 → B1/B2/B3 信号个股 + 质量分 | 是       | `app/routers/candidate.py`、`app/services/candidate_pool/*` |
| 各类策略族 + 信号跟踪 | 信号 / 已验证信号                      | 是       | `app/services/retail/*`、`signal_tracking_service.py`       |
| ETF 雷达       | 行业资金流排名                         | 行业级     | `app/services/etf_radar/*`                                 |
| 单条计划容器       | 手动创建 daily\_plans               | 是       | `app/services/plan_service.py`、`app/routers/plans.py`      |

断掉的桥（缺失层）：

- 宏观 → 行业/主题映射（方向没有约束候选范围）。

- 候选股票 → 当日执行计划（触发价/止损/仓位未自动生成与写库）。

- 宏观约束注入 + 方向锁定机制（方向未设基准，未作为候选过滤/加权条件）。

## 3. 当日方向基准

### 3.1 判定依据与"权威性"定位

当前方向来自 `macro_scorer.py`：把若干市场隐含信号打正负分再累加，越界判"偏多/偏空/中性"。

| 类别   | 具体信号                  | 性质          |
| ---- | --------------------- | ----------- |
| 隔夜外围 | 标普/纳指/恒指/日经/KOSPI 涨跌幅 | 事实数据        |
| 情绪指标 | VIX、富时A50/美股指期货       | 事实数据（盘中会抖动） |
| 事件面  | 高重要性政策/财经日历 + 分级快讯    | 需要解读        |
| 情绪面  | 昨日涨跌家数                | 滞后事实        |

定位结论：**它不是涨跌预言，是"可复现的市场温度"**。用它当"今天买不买/仓位多大"的开关 → 它是权威约束；当"预测哪些股票会涨" → 毫无权威。因此展示上必须区分"事实/分数"与"解读"。

### 3.2 让"当日方向"成立的四项改动

1. **盘前锁定**：以盘前时点（隔夜美股收盘 + 08:30 A50 期货 + 开市前财经日历）生成一次，作为当日基准缓存；盘中不重算标签，只展示基准。直接消除"一天多次翻转"。
2. **置信度门槛**：`confidence < 阈值`（如 30%）时明确"观望/不确定"，并按减半仓位执行，而非硬给一个方向。
3. **与 regime 互证**：叠加 `market_regime_detector.py` 的当日状态（趋势/震荡/风险），比单一分数可信。
4. **数据与解读分层展示**：指数涨跌是多少（事实）与"为什么判偏空"（规则/LLM 解读）分开呈现。

## 4. 编排层速度

拆成两种模式，避免后台长耗时：

- **盘前预生成（推荐，秒级）**：候选池已有结果级 TTL 缓存 + 代码池缩容 + 线程池（`candidate_pool_service.py`）；用调度器盘前跑完整流水（方向锁定 + 行业 → 候选 → 计划写库），用户打开即见成品。唯一的 LLM 宏观解读（10–60s）放后台异步，先展示规则分。

- **盘中一键刷新（秒级 \~ 20–30s）**：默认只更新触发价/止损/实时行情（秒级）；若强制重算行业资金流则约 20s，可设"盘前高频、盘中低频"，做异步任务条显示进度。

结论：数据源全部现成，无需"很长信息搜集时间"。

## 5. 可视化与交互机制

信任来自**可拆解、可溯源、可否决**。以下 5.x 为逐项细化规格。

### 5.1 方向拆解面板（信号溯源）

每个信号一行（实际值 / 权重 / 判定 利多·利空·中性），悬浮查看"该信号如何影响方向"。数据来源：`macro_service.build_macro_snapshot` 返回的 `signals`（已含 name/value/score/weight/detail），前端可直接填充，后端改动很小。

### 5.2 仪表盘式方向 + 置信度

| 元素    | 规格                                                    |
| ----- | ----------------------------------------------------- |
| 刻度条   | 三段：偏空（危险）─ 中性（灰）─ 偏多（成功），指针可动                         |
| 指针位置  | 由基准 `score` 映射到区间百分比；低置信度时固定在"中性/观望"                  |
| 置信度   | 徽标旁显示 `measured_confidence%`（百分数 + 等级文案）              |
| 锁定时间戳 | `当日锁定于 08:30`，与"盘中不重算"一起明确基准语义                        |
| 状态四态  | `偏多 / 偏空 / 中性(观望) / 数据不足`：`中性(观望)` 与 `数据不足` 均不产生多空强断言 |

关键决策：**这不是实时仪表，是"当日基准"的静态快照**。指针仅在盘前生成时定位一次；盘中的行情变动反映在"信号拆解表"的数值更新上，而不是让方向徽标来回翻转。

### 5.3 计划生成流水线（带审计痕迹）

流水线固定四段，每段展示"扫描到什么、按什么规则过滤掉多少"，用户看到的是**决策过程**而非黑箱结果：

```
环境(宏观) → 行业(板块) → 个股(候选) → 计划(daily_plans)
```

| 段  | 输入           | 规则示例（可审计标注）                            | 输出                |
| -- | ------------ | -------------------------------------- | ----------------- |
| 环境 | macro 快照     | 方向/置信度、regime 互证                       | 当日方向基准 + 约束参数     |
| 行业 | 行业资金流 + 资讯主题 | "主题命中 3 个行业，偏空→剔除高风险行业 2 个"            | 当日行业池             |
| 个股 | 候选池 + 已验证信号  | "偏空 → 过滤 12 条 B1 追涨信号，保留 B2/B3 低吸 5 只" | 待写候选              |
| 计划 | 候选 + 行情      | 取触发价/止损，`position_sizer` 反算仓位          | 批量写入 daily\_plans |

审计痕迹结构（每段产生一条可展示记录）：

```json
{
  "step": "行业",
  "scanned": 28,
  "rule": "主题命中 + 偏空剔除高风险行业",
  "kept": 6,
  "dropped": 22,
  "reasons": ["2 个高风险行业被剔除", "20 只个股无 B 信号"]
}
```

前端以"四段链路 + 每段漏斗数字"呈现；`direction=偏空` 等宏观约束必须显式标注在对应段上（如"偏空 → 过滤 12 条 B1 追涨信号"），这是让用户"认账"的关键。

### 5.4 每条计划的"来源 + 人工可改"

自动生成的计划绑定**来源标签 + 人工最后一道闸**：

```json
{
  "code": "920002",
  "direction": "buy",
  "trigger_price": 12.34,
  "stop_loss": 11.60,
  "position": { "suggested_shares": 500, "target_ratio": 0.08 },
  "source": { "type": "signal_verified", "ref": "920002", "label": "来源：已验证信号 920002" },
  "editable": true
}
```

- **来源标签类型**：`已验证信号 <code>` / `候选池 B1，主题命中 <industry>` / `策略族 <strategy>`。

- **一键操作**：`确认`（写状态 pending） / `改价`（改触发价/止损后重算仓位） / `删除`（来源标注"已否决"）。

- **信任机制**：自动生成 ≠ 自动下单。生成结果默认未锁定，必须人工确认后才进入 SSE 触发提醒/执行链路。

## 6. 建议落地路径

1. 方向锁定 + 置信度门槛（`macro_scorer` 取数口径 + 当日基准缓存）——最便宜，先消"方向乱跳"观感。
2. 方向拆解面板（`WarRoom/index.vue` 盘前 Tab，对接 `signals`）。
3. 当日计划编排层（输入 direction/confidence + 候选池行业/个股 + 已验证信号 → 批量写 `daily_plans`）。
4. 宏观 → 行业桥（`news_classifier` 主题 与 候选池强势行业取交集；`direction=偏空` 时过滤 B1 追涨、放大止损）。
5. 用 `position_sizer` 反算仓位、复用 SSE 触发提醒链路，形成"计划 → 成交 → 复盘"闭环。
